## Como reproduzir

Pré-requisito: o stack institucional local já existe no checkout indicado por `--stack-root` (pasta com `.institutional-admin.local`). Nada aqui inicia, reinicia ou reseta o stack.

```powershell
bun --no-env-file run scripts/institutional-app-port.ts --stack-root "<checkout com .institutional-admin.local>" --port 8092
```

```powershell
bun --no-env-file run scripts/institutional-tenant.ts provision --tenant gama --stack-root "<checkout com .institutional-admin.local>"
```

```powershell
bun --no-env-file run scripts/institutional-tenant.ts readback --stack-root "<checkout com .institutional-admin.local>"
```

Depois do `provision`, o plano e a designação são feitos pelo RH no navegador (`/ivo-integral/acoes`), como na prova registrada em `decisions/Q2_LEADER_SCOPE_PROPOSAL_2026-11-18.md`. Links mágicos: Mailpit `127.0.0.1:57624`, buscando pelo destinatário exato.

## O que cada script garante

| Script | Garantia |
| --- | --- |
| `institutional-tenant-guards.ts` | Puro. Recusa Alfa/Beta, nomes fora de `[a-z]{3,12}`, comandos fora de `provision`/`readback` (não há reset), porta 8091 e portas <1024. Sanitiza JWT e hex longos da saída. |
| `institutional-app-port.ts` | Valida o alvo com `institutionalEnv()` do stack-root, roda o preflight `--runtime=local --db=local`, sobe o Vite do checkout atual com `--strictPort` e `ACTION_PLAN` (equivalente a `dev --learning`). |
| `institutional-tenant.ts provision` | `institutionalEnv()` + `requireInstitutionalLocalTarget` antes de I/O. Fluxo real: plataforma → primeiro RH → Q2 por CAS → onda/setor/link → 5 respostas sintéticas → publicação pelo RH (mesmo módulo do centro de controle; a RPC exige `auth.uid()` de membro) → convite `LIDER_EQUIPE` aceito. Cada passo lê o estado antes de escrever. |
| `institutional-tenant.ts readback` | `BEGIN READ ONLY`: por tenant, contagem de RH, lideranças, colaboradores, Q2, planos, ações e ações de liderança. Sem e-mail nem token. |
